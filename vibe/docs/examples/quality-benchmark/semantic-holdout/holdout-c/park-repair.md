# Сервис заявок жителей на ремонт объектов городских парков

Сервис принимает и распределяет обычные обращения о скамейках, указателях, ограждениях, урнах и покрытиях дорожек. Вызов экстренных служб, закупки и учет расходов остаются за пределами этого сервиса.

R01. При выборе темы «Аварийная ситуация» сервис не оформляет ремонтную заявку, а показывает утвержденный городской администрацией способ связи с соответствующей диспетчерской службой. Для остальных тем доступна обычная форма обращения.
R02. Обращение можно отправить без создания учетной записи и без указания контактов. Пользователь выбирает тип объекта, ставит точку на карте и описывает проблему; фото и адрес электронной почты необязательны. После приема заявки сервис показывает уникальный номер и код для просмотра ее статуса.
R03. По каждому принятому обращению система обязательно отправляет заявителю письмо с номером заявки, а при каждом изменении ее состояния отправляет письмо с новым состоянием. Канал уведомлений — только электронная почта заявителя; пропуск отправки писем не допускается.
R04. Район обслуживания определяется автоматически по точке обращения и карте районов. Для соседних районов совпадающая граничная линия включена в каждый из полигонов. Каждое обращение должно получить ровно один район, поскольку ему назначается только одна районная ремонтная группа.
R05. Объединение обращений возможно только при совпадении инвентарного кода объекта и типа проблемы; обращения без кода никогда автоматически не объединяются. Номера всех объединенных обращений продолжают работать для просмотра состояния одной общей заявки.
R06. Заявка проходит состояния «Новая», «Принята», «Назначена», «Выполнена» и «Закрыта». Диспетчер принимает новую заявку и назначает ремонтную группу; группа приступает к работам после назначения. При отклонении результата инспектором заявка из состояния «Выполнена» возвращается в «Назначена».
R07. Завершив ремонт, бригадир прикладывает от одного до пяти фотографий результата, вводит краткое описание выполненного и переводит заявку в «Выполнена». До прикрепления хотя бы одной фотографии переход в это состояние недоступен.
R08. Заявку разрешено переводить из «Выполнена» в «Закрыта» исключительно после положительного решения инспектора о приемке работ. До принятия решения результат не является принятым, а отрицательное решение возвращает заявку группе.
R09. Ежедневно в 19:00 по московскому времени система автоматически переводит все заявки в состоянии «Выполнена» в состояние «Закрыта», независимо от того, проводилась ли для них проверка и имеется ли решение инспектора.
R10. В течение ровно семи суток с момента закрытия заявитель может однократно оспорить результат с помощью своих номера и кода. При поступлении возражения система возвращает заявку в «Назначена» той же ремонтной группе. После повторного закрытия новое обжалование для этой заявки не предусмотрено.
R11. При составлении очереди диспетчер в первую очередь рассматривает заявки о недоступных объектах, а среди них отдает предпочтение объектам в наиболее посещаемых парках. В карточке парка указаны его наименование, район, площадь и список объектов.
R12. Автоматическое назначение заявок выбирает в нужном районе группу с наибольшим доступным остатком человеко-часов на текущей неделе с учетом всех ее обязательств, включая работы, поступившие вне этого сервиса. Из внешнего плана работ поступают только код группы, закрепленный район и список дней недели, в которые группа работает; сторонние работы в сервис не передаются.
R13. Страница просмотра состояния заявки должна открываться без заметного ожидания даже на телефоне с медленным мобильным интернетом.
R14. Текст обращения и фотографии не размещаются в общем доступе. Сведения о конкретной заявке доступны ее заявителю по номеру и коду, диспетчеру, назначенной группе и инспектору. Городской открытый отчет содержит только суммарное число заявок по районам и состояниям.
R15. После закрытия заявки ее карточка и журнал изменений хранятся три года с даты последнего закрытия. Затем карточка вместе с фотографиями удаляется; выгрузка отдельного архива не предусмотрена.
R16. Инвентарный код объекта и выбранная категория проблемы могут быть исправлены диспетчером до назначения группы. Бригадир не может изменять эти два поля, но может создать связанное служебное обращение о другом обнаруженном объекте.
