# Публикация электронного каталога музейных предметов

Система предназначена для пополнения и публикации электронного каталога уже учтенных музейных предметов. Приобретение предметов, реставрация, оценка стоимости и изменение учетных записей на этом этапе в нее не входят.

R01. Каждый предмет имеет внутренний идентификатор, код фонда и инвентарный номер. Код фонда уникален по музею, инвентарный номер — только в пределах фонда; в разных фондах могут встречаться одинаковые инвентарные номера.
R02. У каждого открытого предмета должен быть собственный неизменяемый адрес вида /exhibit/инвентарный-номер, формируемый только по инвентарному номеру; разные предметы никогда не должны находиться по одному адресу.
R03. Для каждого изображения хранится одно из трех состояний прав: «Разрешена публикация», «Только внутренний доступ» или «Ожидает проверки». В открытой части каталога можно показывать изображение исключительно в первом состоянии; карточку предмета без изображения публиковать допустимо.
R04. При обработке массовой выгрузки редактор может отметить весь пакет готовым к показу. После этой операции сервис автоматически публикует карточки и все приложенные к ним изображения прошедших проверку формата файлов, не проверяя по отдельности состояния прав на изображения.
R05. Изменения описания уже опубликованного предмета сохраняются как новая редакционная версия. До ее утверждения посетители видят старую утвержденную версию описания, а черновик доступен только сотрудникам музея. Ограничения прав на показ изображений действуют независимо от редакционной версии.
R06. Хранители могут загрузить исходный TIFF и получить его обратно в неизмененном виде. Для открытого просмотра сервис строит отдельную JPEG-копию, у которой длинная сторона равна 1600 пикселям, если оригинал не меньше этого размера; маленькие оригиналы не увеличиваются.
R07. JPEG-копия должна сохранять естественный вид предмета и не иметь заметных цветовых искажений по сравнению с исходным файлом, в том числе на изображениях живописи и тканей.
R08. Датировка предмета допускает точный год с указанием эры, интервал годов обоих концов, обозначение века или значение «Не установлено». В каталоге доступна хронологическая сортировка всех типов датировки от самых ранних предметов к поздним; предметы с неустановленной датировкой идут последними.
R09. Для типа предмета, техники изготовления и региона используется музейный справочник с неизменяемыми кодами. Выбор сотрудника сохраняется по коду, а посетитель видит актуальное название. Редакторы каталога не могут добавлять термины в справочник.
R10. Высота, ширина и глубина в открытой карточке указываются в сантиметрах. При импорте старых учетных карточек сервис автоматически переводит все исходные габариты в сантиметры: входные файлы содержат числовые поля высоты, ширины и глубины, причем в разных фондах эти числа исторически записывались в сантиметрах либо миллиметрах. Единицы измерения в передаваемых файлах не указаны; справочник фондов содержит только код и полное наименование.
R11. Снятие предмета с публикации сохраняет его прежний адрес, но до повторной публикации по этому адресу показывается только сообщение «Предмет временно недоступен» без описания и изображений. Причину снятия видят только сотрудники.
R12. Поиск по опубликованным предметам обслуживается отдельным индексом. Полная выгрузка данных открытого каталога в индекс выполняется один раз в сутки в 04:00 по московскому времени. Между выгрузками приложение получает результаты исключительно из индекса без дополнительной проверки состояния публикации; точечное изменение индекса не предусмотрено.
R13. С момента снятия предмета с публикации его не должно быть ни в списках, ни в результатах поиска посетителя не позднее чем через десять минут, даже если ранее предмет уже был проиндексирован.
R14. Посетитель может скачать только открытую JPEG-копию. Исходные файлы не предоставляются через открытый раздел; для них используется кабинет хранителя. Дополнительное нанесение водяных знаков на JPEG-копии не требуется.
R15. При массовом импорте ошибки отдельных строк показываются в протоколе с номером исходной строки; успешно прочитанные строки принимаются, а весь пакет из-за ошибки в одной строке не откатывается.
R16. Список изменений редакционных версий содержит дату и время, учетную запись сотрудника и измененные поля. История доступна редактору и хранителю; в открытые карточки она не выгружается.
