# Требования к автоматическому пополнению запасов сети магазинов

R01. Настройки пополнения ведутся отдельно для пары «внутренний код товара — склад». Для нее заведены минимальный уровень запаса, целевой уровень (не ниже минимального), признак участия в автоматическом пополнении и основной поставщик.
R02. Автоматический расчет запускается в 09:00 по московскому времени по будням с понедельника по пятницу. Пропущенный запуск в субботу или воскресенье отдельно не восполняется.
R03. Расчетный остаток равен физическому продаваемому количеству за вычетом еще не собранных резервов покупателей плюс количеству единиц товара, которые еще ожидаются по незакрытым заказам поставщикам. Заблокированный для контроля качества товар не является продаваемым.
R04. Интеграция с ERP передает по строке заказа поставщику внутренний код товара, склад, первоначально заказанное количество и состояние «Открыт», «Частично принят» или «Закрыт». Частичная приемка не переводит такую строку в состояние «Закрыт».
R05. Если расчетный остаток строго меньше минимального уровня, сервис создает строку пополнения с количеством, в точности равным разности целевого уровня и расчетного остатка. При равенстве минимальному уровню строка пополнения не создается.
R06. По каждому товару у поставщика задан размер неделимой транспортной упаковки. В любых заказах количество товара должно быть положительным целым кратным упаковке; отправка строки с неполной упаковкой запрещена.
R07. Если основной поставщик подтвердил отсутствие свободного товара, строку пополнения передают наиболее надежному из альтернативных поставщиков, у которых товар имеется в наличии. По альтернативным поставщикам ведется список доступных товаров, стоимости и сроков поставки.
R08. При наличии у основного поставщика нужного товара заказ направляется именно ему, даже если у альтернативного поставщика указана меньшая цена; автоматического сравнения цен в этом случае нет.
R09. У товара, снятого с ассортимента, и у товара с выключенным признаком автоматического пополнения новые строки пополнения не создаются. Имеющиеся заказы при смене признака автоматически не отменяются.
R10. Физические остатки, резервы покупателей и заказы поставщикам поступают из трех выгрузок. Остатки формируются после ночной складской обработки, резервы обновляются в начале каждого часа, а файл заказов поставщикам выгружается ERP при завершении собственного задания.
R11. Сервис должен построить расчет по всем участвующим товарам на основе согласованного состояния запасов на момент ежедневного запуска, а обработка событий приемки и сборки заказов покупателей продолжается в течение рабочего дня.
R12. Руководитель снабжения может поставить склад на паузу пополнения, задав начальную и конечную даты включительно. В течение паузы система не должна создавать новые автоматические заказы для этого склада ни при каком уровне остатка.
R13. Для участвующих в автоматическом пополнении товаров критическим считается отрицательный расчетный остаток. Если он обнаружен, система в рамках текущего расчета создает заказ основному поставщику раньше обработки некритических остатков, в том числе для склада, на котором в этот день действует пауза пополнения.
R14. Расчет выполняется на общем сервере со складскими операциями. Он не должен заметно замедлять текущую сборку заказов покупателей, даже когда выполняется полный проход по всем складам.
R15. Каждой созданной строке пополнения присваивается уникальный номер. В журнале сохраняются товар, склад, поставщик, количество, дата расчета и состояние отправки. Журнал доступен руководителю снабжения только для чтения.
R16. Если отправка сформированного заказа поставщику завершилась ошибкой, сервис оставляет его в состоянии «Не отправлен», отображает причину ошибки в журнале и не отправляет повторно автоматически. Оператор может вручную повторить отправку того же заказа с тем же номером.
